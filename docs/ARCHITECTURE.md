# 架构说明

## 数据流

```text
用户输入
  │
  ├─ 公历 / 农历 / 闰月
  ├─ 出生日期时间
  ├─ 性别
  └─ 出生地经度
  │
  ▼
输入校验
  │
  ▼
历法与节气转换
  │
  ▼
真太阳时修正
  │
  ▼
四柱核心
  │
  ├─ 十神 / 藏干 / 纳音 / 旬空 / 十二长生
  ├─ 胎元 / 命宫 / 身宫 / 胎息
  ├─ 起运 / 交运 / 大运 / 流年 / 小运
  ├─ 五行评分
  └─ 神煞规则匹配
  │
  ▼
LocalChartAdapter 统一结构
  │
  ▼
POST /api/paipan
  │
  ▼
移动端 / PC 结果页
```

## 核心模块

### `LocalPaipan.ts`

负责历法、节气、四柱、起运、大运等主要计算流程。

### `TrueSolarTimeCalculator.ts`

负责经度差与均时差修正，并输出真正用于排盘的日期时间。

### `ShenShaMatcher.ts`

读取 JSON 规则库，根据来源柱、目标柱、性别和规则类型完成结构化匹配。

### `WuXingScorer.ts`

输出五行统计与评分相关数据。

### `LocalChartAdapter.ts`

负责把内部结果整理为稳定的 API 数据结构，使 UI 和未来的其他调用端尽量不依赖底层实现细节。

## 为什么不用大型框架

当前 HTTP 层使用 Node.js 原生模块，主要为了：

- 运行时 0 第三方 npm 依赖
- 容易部署
- 容易审计
- 将排盘核心与 Web 框架解耦

当项目需要认证、数据库、队列、限流、复杂 REST API 时，可以接入 Fastify / NestJS 等框架，而不需要重写排盘核心。
