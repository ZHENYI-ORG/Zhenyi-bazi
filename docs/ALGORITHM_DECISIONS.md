# 真一盲派排盘算法取舍说明 v1.9.0

本文件记录“真一盲派八字排盘”当前采用的底层排盘口径。目标不是把所有民间口诀混成一套规则，而是以内部研究资料中与盲派做功体系直接对应、重复出现且能够相互印证的资料作为主规则源。

## 1. 主规则来源优先级

当前优先级：

1. 内部核心资料 A
2. 内部核心资料 B
3. 内部系统资料 A
4. 内部核心资料 C 及同系校订材料
5. 盲派函授、课堂笔记、博客整理作为交叉参考
6. 内部补充资料用于民间口诀、心算万年历与其它盲派/江湖方法参考，不作为盲派四柱底层的唯一规则源

## 2. 年柱与月柱

- 年柱以立春为分界。
- 月柱以节令为分界。
- 交节当天必须比较实际交节时刻与出生时间。
- 继续使用现有精确二十四节气算法，不以“银盘子/流年赶月”等近似口诀替代主历法引擎。

## 3. 日界与早晚子时

采用 **0 点换日**：

- 23:00–24:00：夜子时，日柱仍属于本日。
- 00:00–01:00：早子时，日柱属于新的一日。
- 夜子时的时支仍为子，但时干与早子时不同，需要按夜子时规则重新纳干。

工程回归案例：

- 2010-12-09 00:30 → 庚寅 戊子 癸巳 壬子
- 2010-12-09 23:30 → 庚寅 戊子 癸巳 甲子
- 2010-12-10 00:30 → 庚寅 戊子 甲午 甲子

四柱直排时，如果时支为子，同时允许标准早子时时干与合法夜子时时干，避免将夜子时组合误判为“五鼠遁错误”。

## 4. 真太阳时

真太阳时保留，并作为产品默认开启项，但允许用户关闭。

- 开启：使用经度差 + 均时差计算真太阳时，并以修正后的时间进入四柱算法。
- 关闭：直接按输入民用时间进入四柱算法，出生地点不再强制。

这是本项目的产品/工程选择。内部研究资料中的内部资料存在“以北京时间定时辰，不看地方时”的表述，因此本项目不宣称“真太阳时是盲派原法强制要求”。系统通过 `time_basis`、`effective_time` 明确记录本盘实际采用的口径。

## 5. 起运

日期时间排盘采用盲派粗略起运法：

1. 先按阳年男/阴年女顺排，阴年男/阳年女逆排。
2. 顺排取出生后最近节令；逆排取出生前最近节令。
3. 取出生日期与该节令日期之间的日数。
4. 日数 ÷ 3。
5. 余 1 舍，余 2 进。
6. 最小 1 虚岁，最大 10 虚岁。

示例：2005-03-15 男命，乙酉阴年男命逆排，向前取惊蛰 3 月 5 日，相差 10 天；10 ÷ 3 = 3 余 1，因此 **3 虚岁起运**。

原来的精确年月日时折算算法不再决定盲派主盘，但保留为 `qiyun.precision_reference`，用于工程对照和研究。

## 6. 大运顺逆与干支分运

- 大运从月柱顺排或逆排。
- 每步大运仍然是一个完整干支柱，跨度十年。
- 前五年以运干为当运主体。
- 后五年以运支为当运主体。

输出结构：

```text
大运 甲寅
├─ stem_phase   甲运（前五年）
└─ branch_phase 寅运（后五年）
```

每个流年额外输出：

- `dayun_phase`
- `active_dayun_component`
- `active_dayun_value`

判盘 Timing 层默认只让当前当运干/支直接参与。若流年与非当运部分发生资料明确支持的合冲，则允许提前/重新引动该部分。

## 7. 交运

采用年柱纳音五行交运法：

| 年命纳音五行 | 交运规则 |
|---|---|
| 木 | 大寒当日寅时 |
| 火 | 清明前三日午时 |
| 土 | 芒种后九日辰时 |
| 金 | 处暑当日申时 |
| 水 | 冬至前三日亥时 |

五年一交，十年两交，与“大运前五年运干、后五年运支”相衔接。

### 资料异文说明

内部系统资料 A中有一处课堂整理文字将木、水对应写成“水大寒、木冬至”，但内部核心资料 A内部核心资料 B以及同一资料中另一处“关于起运”的写法均为“木大寒、水冬至”。当前系统采用多份核心资料一致的版本：**木大寒、水冬至**。

## 8. 不纳入底层主盘的内容

以下内容不因为出现在“盲派资料”中就自动进入四柱主算法：

- 银盘子、流年赶月等心算万年历近似口诀
- 一掌经起宫法
- 各地江湖口传的独立排法
- 无法由多份核心核心研究资料交叉确认的单条异文

这些内容可以以后作为“口诀校验/研究模式”单独实现，不应覆盖当前盲派主盘。


## 9. v1.5：交运必须进入真实时间轴

从 v1.5 起，“木命大寒寅时、火命清明前三日午时、土命芒种后九日辰时、金命处暑申时、水命冬至前三日亥时”不再只作为文字说明。

程序会：

1. 计算目标交运年份对应节气的精确公历日期；
2. 按规则加减日数得到交运日；
3. 以传统时辰保存交运窗口（例如亥时为 21:00—23:00）；
4. 用该窗口作为首运、运干转运支、下一步大运的真实切换边界。

注意：原始规则只给“某日某时辰”，没有提供分钟，因此系统不伪造单一精确分钟，字段标记为 `double_hour_window`。节气本身保留精确时刻用于确定“哪一天是节气日”。

## 10. 交运年不是整年只有一个运

交运发生在一年中的具体日期，因此交运年可能同时包含前后两个阶段。

例如水命某年冬至前三日亥时由“戊运”交“寅运”：

- 交运窗口之前：仍按戊运；
- 交运窗口之后：进入寅运。

年度流年卡只是一年容器，不能再用 1 月 1 日机械切换。当前岁运判断以实际日期和交运窗口为准。

## 11. 大运前后五年的重新引动

当前采用的盲派规则是：

- 前五年运干为主，运支退为体/象；
- 后五年运支为主，运干退为体/象；
- 非当运部分并非永久删除。流年若与其发生资料明确支持的合、冲、刑、穿、破或同字并临等作用，可提前/重新引动。

程序因此不再只检测“六合/六冲”，而是统一生成结构化 `LuckRelationFact` 风格的岁运关系记录。

## 12. 四柱大限

盲派多数核心资料将四柱同时作为人生阶段背景：

- 年柱：约 1—18 岁；
- 月柱：约 18—35 岁；
- 日柱：约 35—55 岁；
- 时柱：约 55 岁以后。

09 年广州课堂整理稿出现“日 36—55”的异文。当前系统采用多数核心资料的 35—55 版本，但将 18、35、55 等边界视为交叠过渡，不把大限当作精确到生日的硬切换，也不允许大限覆盖明确的大运流年事实。

## 13. 小运的产品权重

小运数据继续保留，以兼容传统排盘与研究用途；但当前盲派做功主线与 Timing 仲裁不把小运放在与“大运、流年”同等权重的位置。后续若增加小运参与判断，必须单独建立来源规则与回归样例。


## 14. v1.6：海外民用时间与真太阳时

真太阳时开关继续默认开启，但时间输入先被视为**出生地当地民用时间**。

- 中国省市区快捷选择使用 `Asia/Shanghai`；
- 海外 / 手动地点允许 IANA 时区（如 `America/New_York`）与 -180°—180° 经度；
- IANA 时区按出生日期解析当地实际 UTC 偏移，因此夏令时会进入民用时间→UTC 的转换；
- 春季 DST 跳时导致的不存在当地时间不静默猜测；
- 秋季 DST 回拨导致的重复当地时间保留 `civil_time_ambiguous` 标记，而不是伪装成唯一答案。

这一层属于现代时间工程能力，不宣称为古籍中的盲派规则。核心研究资料本身只明确“中国按北京时间、外国按当地时间”；真太阳时仍是本产品默认开启、用户可关闭的增强校时口径。

## 15. 流年以立春为界

流年干支不能按公历 1 月 1 日机械切换。当前系统用精确立春事件作为流年起止边界：

- 当年立春之前：仍属于上一干支流年；
- 当年立春之后至下一年立春：属于当年干支流年。

每个流年保存 `liunian_start_event` / `liunian_end_event`，当前 Timing 通过事件时间判定真实流年。

## 16. 流月以十二节令为界

流月采用十二“节”切换，而非公历每月 1 日或农历初一：

- 寅：立春→惊蛰
- 卯：惊蛰→清明
- 辰：清明→立夏
- 巳：立夏→芒种
- 午：芒种→小暑
- 未：小暑→立秋
- 申：立秋→白露
- 酉：白露→寒露
- 戌：寒露→立冬
- 亥：立冬→大雪
- 子：大雪→小寒
- 丑：小寒→立春

月干按五虎遁从对应流年年干推出。程序只动态计算“当前流月”，不把全部 1440 个流月节点冗余塞进命盘对象。

核心研究资料明确提出“断流月要加入体用思想”。因此 v1.6 中流月参与 `luck_relations` 与细化应期，但**不能单独改写大运 / 流年已经形成的结构吉凶**。

## 17. 地点坐标精度

内置中国行政区数据存在少量经纬度回退到上级行政区中心点的情况。v1.6 将坐标质量保留下来并在 UI 提示“行政区中心估算”。

接近时辰边界的命例若使用估算坐标，应允许用户改用手动经纬度复核。系统不得把回退中心点包装成精确出生坐标。

## 18. v1.7：交运“前三天 / 后九天”采用包含式虚数计数

核心资料一方面写“清明前三天、芒种后九天、冬至前三天”，另一方面明确补充“包括节气这一天”，并称这些天数为虚数。因此 v1.7 将口诀数字与公历日期偏移分开保存：

- 口诀“前三天”仍记录 `traditional_count_days = -3`，公历落日使用 `calendar_offset_days = -2`；
- 口诀“后九天”仍记录 `traditional_count_days = 9`，公历落日使用 `calendar_offset_days = 8`；
- 当日规则偏移为 0。

字段 `counting_mode = traditional_inclusive` 明确记录该取舍。由于现有核心资料尚未找到一条把“前三天”完整换算成具体公历日期的逐日演算案例，此规则同时保留来源说明，后续如获得本门派标准案例，应优先用案例回归验证，而不是隐去这一不确定性。

## 19. v1.7：岁运先做身份解析，再做应期关系

核心研究资料把“出现、通禄、原身、藏干”列为应期入口。v1.7 因此新增 `LuckIdentityResolver`，先回答“岁运这个字在当前命局里取得谁的身份”，再把该身份交给关系与 Timing 仲裁。

A级直接身份：

- 同天干 / 同地支到位；
- 固定禄：甲寅、乙卯、丙戊巳、丁己午、庚申、辛酉、壬亥、癸子；
- 固定原身：寅甲、卯乙、巳丙/戊、午丁/己、申庚、酉辛、亥壬、子癸；
- 原局藏干在岁运天干透出；
- 原局明透天干在岁运地支中以藏干形式出现。

明确禁止：辰、戌、丑、未没有直接天干原身，不能因为它们属土就主观配置为戊或己。

B级身份只作候选：

- 丁未、癸丑半禄；
- 课堂整理笔记中的“乙到：卯→未→辰→乙”身份顺序。

B级候选默认 `major_eligible=false`，除非未来有更高等级资料或足够原书案例完成升级。

## 20. v1.7：大运阶段门与反客为主

“原局定题、大运定阶段、流年取应”不再只存在于提示词，而进入确定性 Timing。

`stage_gate` 先检查当前大运是否通过直接身份或结构关系承接了原局第一主线。若未承接：

- 流年关系仍记录；
- 但标记为 `timing_clue_only`；
- 不单独改变重大事件结论。

`fan_ke_wei_zhu` 分两类：

1. **original_identity**：流年通过同字、固定禄、固定原身取得原局主线节点身份，同时大运在同一目标上已有承接；
2. **dayun_identity**：大运先出现某字，流年再通过该字之禄、原身或同字取得“大运这个字”的身份。该路径用于表达原书“甲申运—戊寅年”一类先有大运人物/主题、再由太岁反客为主的结构。

即使 `fan_ke_wei_zhu.qualified=true`，最终事件仍必须回接原局人物、宫位与做功主线，不能把反客为主本身当作吉凶结论。

## 21. v1.7：非当运部分的身份重新引动

前五年/后五年只决定主次，不把另一半永久删除。v1.7 在原有合、冲、刑、穿、破重新引动之外，增加两条高置信身份引动：

- 后五年走运支时，流年地支若为运干固定禄，可重新引动运干；
- 前五年走运干时，流年天干若为运支固定原身，可提前引动运支。

半禄和墓气/余气代表关系暂不用于跨阶段重新引动。

## 22. v1.7：墓库改为状态机，不再“五行见墓就算入墓”

当前高置信墓库白名单：

- 亥 → 辰；
- 寅 → 未；
- 巳 → 戌；
- 申 → 丑；
- 丑 → 辰；
- 未 → 辰（同时受丑未冲等例外限制）。

子、午、卯、酉见对应墓库时，因半合/中神关系不自动判入墓。丑、未、辰同见时，当前按核心资料的冲突门处理，不机械让丑、未同时入辰。

`tomb_states` 区分：

- `contained`：稳定对应已经形成；
- `store_arrives / inmate_arrives`：岁运把墓库或入墓对象带到；
- `clash_tomb_candidate`：冲墓候选；
- `combine_tomb_candidate`：合墓候选；
- `needs_arbitration`：资料语义存在上下文差异，必须继续检查实际入墓对象、岁运层级、原局意向和结果归属。

尤其不设全局规则“流年冲墓 = 开库”。资料中同时存在流年冲墓取开与特定案例“大运冲才开、年冲不开”的表述，因此开、出、动、破必须进入后续仲裁。


## 23. v1.8：盲派刑 / 破使用专属 Relation Profile

生产 profile `blind_core_v1` 不再复用常见命理“六破 / 自刑”表。核心口径：

- 子卯、卯午归 `break`，可反向；
- 子卯不归 `punish`；
- 辰、午、酉、亥自刑不进入核心生产规则；
- 寅巳申两字分别以穿、冲、合为主，三字齐全时再新增 `sanxing` 成组事实；
- 丑未以冲为主，丑戌、未戌可记 pairwise 刑，三字齐全时再强化三刑；
- 午酉破保留 B 级研究候选，不进入生产 RelationFact。

这样做是为了避免“普通八字关系表”混入盲派主引擎。

## 24. v1.8：身份解析与主线相关性彻底解耦

`LuckIdentityResolver` 现在先依据来源等级与直接性独立解析岁运身份，再标记 `mainline_relevant`。主线不得参与身份选择。

A级直接身份可同时存在，例如乙流年遇原局明乙与卯时，可同时保留“乙同字到位”和“卯原身到位”。课堂“乙到：卯→未→辰→乙”只作为 B 级 `school_priority_hint`，生产默认不得覆盖 A 级身份。

## 25. v1.8：冲 / 合进入 TimingRelationSemanticResolver

原始 `clash / combine` 只表示关系事实，不再直接推导“完成、削弱、凶、吉”。

当前至少区分：

- 流年冲原局：默认 `clash_move_candidate`，后续再辨冲动、冲旺、冲出、冲去、冲破、冲凶；
- 冲墓：`clash_tomb_candidate`，不自动开库；
- 流年冲当前当运大运：`clash_active_dayun_candidate`，允许冲去 / 暂时失效 / 冲动候选；
- 流年冲非当运部分：先按冲起 / 提前引动；
- 流年合原局：`combine_candidate`，后续再辨合留、合动、合绊、合去、合伤；
- 流年合大运：先按合动。

`timing.effect` 因此改成保守状态：`neutral / stage_context / activated / identity_triggered`，不再由一条冲合直接输出 `complete / weaken`。

## 26. v1.8：墓库采用当前状态快照

`tomb_history` 保存历史发现，`tomb_state_snapshot` 重新计算当前有效状态，`tomb_states` 作为当前 active states 的兼容别名。

新的时间层进入后，旧的 `contained` 不保证继续有效。例如原局丑入辰，流年来未后形成丑未辰同见，则当前快照撤销机械 `丑入辰 contained=true`，而不是继续累积互相冲突的事实。

冲墓 / 合墓只进入 `store_actions`，不会自动修改 `contained` 为 released / closed。

## 27. v1.8：未来年份不做“关系数量评分”

删除 `future.intensity`、`strong / medium / quiet`。未来五年仅返回：

- `timing_candidate`：存在与第一主线的直接到位 / 合冲刑穿破线索；
- `no_direct_trigger`：暂未发现直接线索，但不等于“平稳”或“无事”。

任何具体年份要升级应期，仍须在该年份重新执行：身份解析 → 大运阶段门 → 关系语义 → 墓库当前状态 → 原局主线回接。


## 28. v1.9：根气不再使用统一加分制

v1.8 及以前会把四柱所有地支中的同干、同五行藏干与固定禄累加成一个 `root_score`。这会混淆“坐下通根/得气”和“其它柱外援”。

v1.9 改为分层事实：

- `seat_direct_root`：坐下藏同干；
- `seat_lu_root`：坐固定禄；
- `seat_longsheng_qi`：坐长生得气；
- `seat_tomb_qi`：坐墓库得气；
- `seat_residual_qi`：坐余气，明确为弱得气；
- `external_lu_support / external_same_stem_support / external_same_element_support`：其它柱只记外部支持，不与“坐下通根”混名。

核心资料明确把“坐墓”“坐余气”称为通根得气，同时又强调余气虽有气但无力，因此不使用一个总分把它们等权累加。工程上 `root_score` 废弃，改用 `capacity_status` 与来源明细。

## 29. v1.9：岁运只重演原局第一主功，不允许换题

`timing.state_replay.mode = original_mainline_state_replay`。

状态重演的原则：

1. 原局第一主功是主题锚点；
2. 大运加入后只判断该主功是否进入阶段、被补足、被解开、受阻或结构发生改变；
3. 流年在大运状态之上找具体到位/引动；
4. 流月只继续细化，不反向创造重大主题。

当前输出保守使用 `candidate`：例如原局合逢岁运冲时只记 `original_combine_released_candidate`，不直接写“反局/离婚/破产”等现实结论；具体吉凶继续由关系语义、宾主、归属和原局结构仲裁。

## 30. v1.9：大运阶段门不再由普通生克单独打开

资料虽强调大运要看对原局的生克作用，但“重大事情进入应验阶段”还要求大运对原局主题有实际体现。v1.9 因此区分：

- `explicit`：同字/固定身份/冲合刑穿破等直接结构命中；
- `replay_confirmed`：State Replay 确认第一主功的有效状态发生改变；
- `shengke_context_only`：只有普通生克背景，不打开重大应期门；
- `quiet`：未承接主线。

这是为了避免“大运只生/克到一个相关五行 → 任意流年都可以升级大事”的过宽判断。

## 31. v1.9：组合只确认 formation，不自动确认 transformation

`timing.composite_state` 会累计原局 + 当前大运 + 流年 + 流月的地支，识别完整三合、三会、三刑是否在某一时间层形成。

但工程上继续分开：

- `formation`：组合是否形成；
- `transformation`：参与节点是否功能改性；
- `ownership`：结果归谁。

当前 `transformation` 默认 `not_auto_assumed`。只有形成组合本身是确定事实，不能因为三合齐全就自动把所有参与字“改成同一五行”。
