# v2.0 专业岁运工作台

v2.0 只升级结果页的岁运信息架构与交互；核心排盘 / 做功 / State Replay 引擎仍为 `1.9.0-state-replay-root-strata`。

## 信息层级

专业岁运页固定按以下顺序组织：

```text
原局第一主功
  ↓
大运：定阶段（十年整柱，前五年运干 / 后五年运支）
  ↓
流年：取应期（立春切换）
  ↓
流月：作月份定位（十二节令切换）
```

流月不得单独创造原局没有的重大事件。

## 流月加载

主 `/api/paipan` 不为 120 个流年预埋 12 个流月。用户选择某个流年时，页面调用 `/api/liuyue` 只生成该年的 12 个流月，并按流年年份缓存。

这样避免单盘长期携带约 1440 个流月对象，同时保留完整流月浏览能力。

## 历史 / 未来流月 State Replay

当用户选择的不是当前真实流月时：

1. 读取该流月精确节令 `start_event`；
2. 在节令时刻后加 2 分钟，避开恰好等于边界的瞬间；
3. 调用 `/api/judgment` 的 `now` 参数；
4. 仍由同一 v1.9 引擎重新判断当时的大运、运干 / 运支、流年、流月与第一主功状态。

页面禁止用“今天”的 State Replay 结果替代历史 / 未来月份。

## 流月内含大运交接

大运交运时刻与流月节令边界不是同一套时间轴。因此一个流月内部可能出现：

- 新一步大运正式起运；
- 运干五年转运支五年；
- 当前大运交出。

如果所选流月内存在上述节点，页面显示“含交运节点”，并明确：**当前历史重演代表流月月初状态，节点前后需要分别查看，不能把整个月视为一个不变的大运状态。**

## 七柱联排

专业表格按：

```text
流月 | 流年 | 大运 | 年柱 | 月柱 | 日柱 | 时柱
```

展示十神、天干、地支、藏干、副星、纳音等。当前未建立流月神煞生产规则，因此流月神煞显示 `—`，不从其它层复制或猜测。

## State Replay 审计区

可视化字段包括：

- 原局 → 大运 → 流年 → 流月状态；
- 大运阶段门；
- 岁运身份；
- 根气阶段变化；
- 墓库当前状态；
- 反客为主候选；
- 当前效应；
- 组合状态；
- 当前时点触发依据。

所有 candidate 状态仍表示“已发生结构变化，需要继续仲裁”，不自动翻译成吉凶或事件完成。
